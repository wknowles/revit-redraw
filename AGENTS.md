# AGENTS.md

## What this repo is
- Two numbered Dynamo graphs for Revit; run order is the filename order:
  1. `1. Create Redraw.dyn` — saves/synchronizes the active Main, creates a detached Redraw copy, and writes a `<title>.baseline.json` sidecar.
  2. `2. Compare and Update Redraw.dyn` — opens the Redraw as a separate document, plans/applies parameter and geometry changes, then closes it. Nothing is linked into Main, so Undo is one step, and each cluster is applied in a sub-transaction so a failed cluster rolls back on its own.
- There is no build system or package manifest. The repo is under git. The real source is Python embedded in each `.dyn` JSON at `Nodes[].Code` (one `PythonScriptNode` per graph); the surrounding nodes only feed `IN` and read `OUT`. Offline tests live beside their sources (`src/test_*.py`, `phase0/test_probe.py`).
- `phase0/` holds a diagnostic probe, not part of the 1→2 workflow: `phase0/Phase 0 Prototype.dyn` answers the runtime questions the Revit API docs cannot answer before the merge is rebuilt. Its Python source of truth is `phase0/phase0_probe.py`; the `.dyn` is generated by `python3 phase0/build_dyn.py` and checked with `python3 phase0/build_dyn.py --check`. Do not hand-edit the generated `.dyn`. `python3 phase0/test_probe.py` drives the probe through stubbed Revit models to check its control flow offline.
- `src/` holds the rebuilt merge logic. `src/graph2.py` is the source of truth for the Python inside `2. Compare and Update Redraw.dyn`; `src/build_graph2.py` injects it into the graph and leaves the node layout alone (`--check` verifies). `src/merge_core.py` is the pure-Python wall matching and clustering engine - no Revit imports - unit tested by `src/test_merge_core.py`. **Edit the `.py` files, not the `.dyn`.**
- `tools/` holds the static checks. `python3 tools/check_repo.py` runs them all: the graphs are valid CRLF JSON with compiling embedded Python, the generated graphs match their sources, the probes and the merge core pass their offline tests, and **every Revit API call matches the Revit 2027 documentation**. `tools/revit_api_2027.json` is a cached index of the documented API, refreshed with `python3 tools/build_api_index.py` (needs network access). The Revit API changes between releases, so run the audit after any Revit upgrade.
- Supporting docs: `CHANGELOG.md` (what changed and when), `DESIGN.md` (current flows, baseline contract, decisions, API facts), `ROADMAP.md` (limitations, deferred features, in-Revit test checklist), `PRIVACY_AUDIT.md` (pre-publish PII audit and checklist), `HANDOFF.md` (working notes for the current rebuild), and `Revit Floorplan Redraw Process User Guide.md` (operator-facing guide). The user guide is written in Simplified Technical English; update it in the same change as any user-visible behaviour, input, default, status, or output. Read these before planning new features.

## Runtime constraints
- Revit 2027, Dynamo 4.0.2, CPython3/PythonNet3. Scripts import `clr`, `RevitAPI`, `RevitServices` and use the Dynamo-injected `IN`/`OUT` globals, so they cannot run under plain Python.
- `.dyn` files are CRLF JSON with Python stored as escaped `\r\n` strings. Preserve encoding/line endings when editing by hand; prefer editing the graph in Dynamo.
- The Directory inputs ship blank; select the target folder in Dynamo before running either graph. This is intentional so local paths are not published.

## Workflow gotchas
- Graph 1 always saves the active Main, or synchronizes it with central when workshared, before extracting the baseline and copying. The old `Save Before Creating Redraw` boolean no longer exists.
- After graph 1 the Redraw is saved and **closed**, and Main is active again. The intended workflow is: close Main, open the Redraw, edit/save/close it, reopen Main, then run graph 2. Graph 1 attempts the same end state for local, cloud and workshared sources; if activation/cleanup fails, the Summary says so and QA names what to close manually.
- Graph 1 refuses to run if the target `.rvt` or `.baseline.json` already exists; delete/rename the pair to regenerate.
- Graph 2 requires the directory to contain exactly one primary `.rvt` (backup files matching `*.NNNN.rvt` are ignored) and exactly one `*.baseline.json`. Run it from Main with the Redraw closed; it fails if the Redraw is the active/open document. Graph 2 opens the Redraw itself for reading and closes it at the end.
- Graph 2 is a dry run when `Apply Updates` is false; the saved graph defaults it to **false**, so a fresh run only previews. The saved graph sets `Redraw Wins On Conflicts` to **true**; the code's fallback is false when the input is missing. A dry run is one transaction (`Redraw Merge Preview`, which also clears the previous preview), an apply is two (`Redraw Merge - Clear Preview`, then `MVP2.4B6 - Merge Redraw Updates`). Each cluster runs in a `SubTransaction` of the merge: a failed cluster is rolled back while the successful clusters still commit, and every `Commit()` status is checked. Undo is one Ctrl+Z on the merge transaction, but the preview clear commits first in its own transaction, so undoing the merge does not bring the bands back — and a cluster that rolled back was never applied.
- Graph 2 refuses a blank Directory, a tolerance that is not a number or is negative, and a spacing that is not positive, each with a message that names the input; a `Location.Move` that Revit refuses fails that cluster instead of being ignored.
- `Summary['Status']` is `SUCCESS`, `SUCCESS WITH WARNINGS` (a skipped cluster or a conflict) or `COMPLETED WITH ERRORS` (a failed or verification-failed change); `Summary['Message']` carries the first reason. `Summary['Audit']` is `OK`, `FAILED` or `SKIPPED`.
- Each run appends `merge-log.csv` and rewrites `merge-summary.csv` next to the Redraw (both gitignored). A fatal run writes a `RUN FAILED` row when it can, and says `SKIPPED` when there is no folder to write to.
- Graph 2 does **not** create a Revit link. Loading a link clears Revit's undo history and the link type can never be removed by the same undo that removes the merge, so the Redraw is read from a document opened on the fly instead. Graph 1 writes the Redraw as a copy of Main (`Application.CopyModel`/detached `SaveAs`), so its internal coordinates are Main's and no transform is needed.
- A stand the Redraw added gets its Room **and** Room Tags: one tag per view that already carries Room Tags, with the type that view uses, placed on the Room's location point. Tags of a moved stand are re-centred in every view that has them (not just the active view).
- The preview bands are marked in their element name (`REDRAW MERGE PREVIEW v=<view> w=<walls>`), and the next run sweeps every view's overrides for the preview colours, so a leftover preview is always removed by the following run.

## Cross-script contract
- Baseline JSON uses `schema_version: "1.0"`, `snapshot_type: "REDRAW_BASELINE"`, and `stands` keyed by Room Number. New baselines use `extraction_settings.boundary_location: "Center"`; Graph 2 accepts `"Center"` or legacy `"Finish"` and uses the same location for Main, Redraw and verification. Graph 2 also validates schema/snapshot, `redraw.filename`, `redraw.sidecar_filename`, and the source project number when both sides have one.
- Baseline coordinates/measurements are Revit internal units (feet); graph 2's tolerance and spacing inputs are metres and converted internally.
- Graph 1 audits 9 parameters (includes `Corners`, `Stand Length`, `Stand Width`); graph 2 only compares/updates 6 (`Floorplan Hall/Pavilion/Sector`, `Obstruction Area`, `Product Code`, `Custom Area`). Keep both lists in sync only if the business rules change.
- Baseline stands include level, phase, design-option, and workset metadata; graph 2 skips geometry moves when Main or Redraw Room levels do not match the baseline.
- Geometry updates remain conservative but no longer "skip added/removed": a stand the Redraw added is created (Room, merged parameters, tags), a stand it deleted is deleted, and existing stands are moved/resized. Everything else is gated: only `REDRAW_ONLY` changes, both boundaries must be entirely unshared walls of the types `Closed Wall - RX` / `Open Wall - RX`, Room Separation Lines are unsupported, and a cluster is **skipped and reported** when a created/replaced wall's type or level is missing in Main, when a Main wall it would touch hosts a `FamilyInstance` or `Opening` (door/window/opening), when a Room Number is duplicated (the cluster is quarantined), on a level mismatch, or on a conflict unless `Redraw Wins On Conflicts` is set. Duplicate Number and blank-Number Rooms are unmanaged, and every wall they share is protected from deletion. Wall type/height/offset/flip/level changes are detected even when the wall did not move. When `Redraw Wins On Conflicts` resolves a stand that was re-created in the Redraw (same Number, no shared wall element id), Main's version of that stand is replaced wholesale, including walls that would otherwise count as later Main work.

## Output wiring gotcha
- Graph 1: `OUT = (summary, qa)`; code block `0;1` maps them to Summary and QA.
- Graph 2: `OUT = (summary, pout, gout, issues, qa)`. All five are wired: a code block `0;1;2;3` feeds four `List.GetItemAtIndex` watches (Summary, Parameter Updates, Geometry Updates, Conflicts / Skips) and a second code block `4` feeds the QA / Errors watch. If you reorder `OUT`, update both code blocks and the `List.GetItemAtIndex` nodes.

## Verification without Revit
- Validate JSON: `python3 -c "import json;json.load(open('1. Create Redraw.dyn',encoding='utf-8-sig'))"`.
- Syntax-check embedded code by extracting `Nodes[].Code` and running `python3 -m py_compile` on it. Imports still fail at runtime; this only catches syntax errors.
- `python3 phase0/build_dyn.py --check` fails if the generated probe graph is out of date with `phase0_probe.py`.
- `python3 src/build_graph2.py --check` fails if graph 2 is out of date with `src/graph2.py`.
- `python3 phase0/test_probe.py` runs the probe against stubbed Revit models (walls, non-walls, unplaced, no rooms) and fails if the probe crashes.
- `python3 src/test_merge_core.py` unit tests the wall matching and clustering engine.
- `python3 src/test_graph2_plan.py` tests graph 2's planner and apply path against stubbed Revit models: safety gates, audit rows, statuses, input validation.
- `python3 tools/check_repo.py` runs every static check at once, including a check that no module-level assignment shadows a function name (graph 2's main body is module level, so a loop variable called `state` used to overwrite the `state()` reader). `python3 tools/check_api.py` on its own audits the Revit API usage against `tools/revit_api_2027.json`, and `tools/check_calls.py` checks every call's arguments.
- Real verification requires opening each graph in Dynamo inside Revit with a suitable project.
